# Kvestefi — что исправлено и как проверено

Версия сборки: debug APK (аналог 2.9.3), база v19.
Проверка: живого эмулятора Android 14 (x86_64), данные читались напрямую из SQLite.

---

## 1. Главный баг: «выдал 10 заданий — ученик видит 5»

### Причина (подтверждена данными)
В `Assignments.kt` подбор задач обрывался на размере выбранной темы:

```kotlin
val chosen = exact.ifEmpty { pool }
return chosen.take(limit.coerceAtLeast(1))   // больше, чем есть в теме, не взять
```

Факты из базы эмулятора:

| Показатель | Значение |
|---|---|
| Всего задач в банке | **154** |
| Самая крупная тема | «Орфография/ОГЭ» — **9** |
| «Геометрия/ОГЭ» | **5** |
| Тем с 10 и более задачами | **0** |

То есть запрос на 10, 15 или 20 задач **всегда** молча обрезался: больше 9 взять было неоткуда.

### Исправление
В `Assignments.kt`:
* подбор идёт по приоритету **тема → уровень → весь предмет**, без дублей;
* количество **добирается** из банка, а не обрезается;
* добавлен `availableCount()` — учителю честно сообщается, сколько задач в теме:
  «В теме только 5 — остальные добавлены из других тем предмета».

### Проверка на живом устройстве
Выбрано: Математика → ОГЭ → **Геометрия** → количество **10** → «Выдать задание».

Результат в базе:

```
задание 1 | тема=Геометрия | задач=10 | ids=29,18,22,14,3,12,24,8,2,1
```

Состав: `3, 14, 18, 22, 29` — **все 5 задач темы «Геометрия/ОГЭ»**,
`1, 2, 8, 12` — пополнение из «Алгебра/ОГЭ», `24` — из «Задачи/ОГЭ».

Итог: **10 задач вместо прежних 5.** ✅

## 2. Защита от повторов заданий

### Причина
`tasksFor` всегда брал `ORDER BY RANDOM()` по всему банку и **никак** не исключал уже выданные задачи.

### Исправление
Добавлен параметр `excludeIds` и метод `issuedTaskIds(teacherId)`, который собирает
задачи из всех ранее выданных заданий. Уже выданные не повторяются, пока банк не исчерпан;
если банк исчерпан — повтор разрешён, но нужное число всё равно выдаётся.

Подключено в `AssignActivity.issue()` и `BadgesFragment.createAssignment()`.

### Проверка на живом устройстве
Второе задание с теми же настройками:

```
задание 2 | тема=Геометрия | задач=10 | ids=5,27,4,11,21,25,9,15,17,7
```

Пересечений с первым заданием (`29,18,22,14,3,12,24,8,2,1`) — **ноль**. ✅

## 3. Задания по Wi-Fi не были видны ученику

### Причина
`LanSync.importRemote` писал задание с `school = ""`, а `forStudent` требовал
совпадения школы — пустая строка не совпадала ни с чем, и задание отбрасывалось.

### Исправление
Пустая школа теперь считается «любой»:

```kotlin
(a.school.isBlank() || a.school.equals(student.school, true)) && ...
```

## 4. Обмен по Wi-Fi всегда показывал «связи нет»

### Причина
`LanSync.ping/pullAssignments/pushResults` вызывались из обработчиков кнопок, то есть
в главном потоке. При `targetSdk 34` это даёт `NetworkOnMainThreadException`,
который ловился `catch (e: Exception)` и превращался в `null` → пользователь всегда
видел «Не удалось связаться». Исключения не было, но функция не работала вообще.

### Исправление
Сетевые операции в `BadgesFragment` перенесены в отдельный поток,
результат возвращается через `runOnUiThread`. Пользователь видит «Подключаюсь…».

## 5. Поддержка: статусы и ответ разработчика

### Причина
Было всего два состояния (`open`/`closed`), поля ответа не существовало,
у разработчика была одна кнопка «Закрыть».

### Исправление
* Схема (версия 18 → 19): колонки `reply`, `replied_by`, `replied_at`;
* статусы: **Ожидает ответа / На рассмотрении / Закрыто**;
* метод `reply()` — ответ сохраняется и переводит обращение в «На рассмотрении»;
* в интерфейсе: кнопки «Ответить», «Взять в работу», «Закрыть обращение», «Открыть заново»;
* пользователь видит ответ, его автора и дату прямо в своём обращении.

### Проверка на живом устройстве
Гость отправил обращение «Test support guest» (тема «Вопрос»).
Появилось в разделе «Мои обращения»:

```
Вопрос · без имени
11.10.2026 18:48 · Ожидает ответа
Test support guest
```

Статус отображается, обращение видно. ✅

## 6. Гость не видел своих обращений

### Причина
`mine(login)` фильтровал по `from_login`, а у гостя он пустой — список всегда был пуст.

### Исправление
Добавлен `guest()`: гость видит обращения, отправленные с этого устройства без входа.

## 8. Побочная находка (сборка)

Проект **не собирается** из пути с кириллицей: Android Gradle Plugin падает с
`Your project path contains non-ASCII characters`. Решения:

* собирать через junction без кириллицы (`C:\kvest`);
* в `gradle.properties` добавлено `android.overridePathCheck=true`.

## 9. Вход и регистрация убраны из приложения

### Причина
До первого квеста было 3–4 лишних экрана: вход с формами «Вход» и «Регистрация»
(ФИО, дата рождения, почта, школа, класс, пароль), а затем приветственный шаг
«Привет! Я — Квестефи». Для быстрого показа это слишком долго.

### Что сделано
* `MainActivity`: при первом запуске сразу открывается `OnboardingActivity`, профиль
  гостя выставляется автоматически (`currentUserId = 0`, роль `guest`);
* `OnboardingActivity`: шаг 0 (приветствие) убран из потока — настройка начинается
  с «Как тебя звать?» (имя, пол, аватар), затем предметы и цель; индикатор
  показывает 3 шага вместо 4;
* `AuthActivity`: переключатель «Гость / Вход / Регистрация» скрыт, экран оставлен
  только как быстрый профиль по имени — вход и регистрация из интерфейса недоступны
  (код сохранён, вернуть можно одним коммитом);
* `SettingsActivity`, `BadgesFragment`: «Выйти из аккаунта» → «Сменить профиль»;
* из подзаголовка онбординга и текста приветственного шага убрано упоминание ВПР.

### Проверка на эмуляторе (Android 14, x86_64)
Чистая установка и `pm clear`, запуск с нуля: шаг 1 «Как тебя звать?» → имя `Yaroslav`,
аватар 🦊 → шаг 2 «Что готовим?» (Математика, Русский язык, История) → шаг 3
«Твой план» («Yaroslav, план готов») → «Поехали!» → главный экран с приветствием.
Повторный запуск сразу открывает главный экран, без онбординга.
В логе `AndroidRuntime:E` пусто — падений нет.

## Что ещё требует работы (не сделано)

1. **Переписка учитель–ученик по локальной сети.** Сейчас сообщения пишутся только в
   локальную базу устройства, и в маршрутах мини-сервера (`LanServer.route`) для них
   **нет ни одного эндпоинта**. Чтобы переписка работала между двумя телефонами, нужен
   обмен по сети и общий ключ пользователя (логин), потому что `id` на каждом
   устройстве свои.
2. **Автопоиск учителя.** Уже реализован (`LanSync.discover`), но рассылка идёт на
   `255.255.255.255` без захвата `WifiManager.MulticastLock` — на многих устройствах
   broadcast блокируется, и человек снова вбивает IP вручную. Нужен `MulticastLock`
   и список найденных учителей вместо `firstOrNull()`.
3. **Потеря задач после «Сбросить прогресс».** `Repository.resetAll` пересоздаёт таблицу
   `tasks`, но не трогает `assignments` — старые `task_ids` начинают указывать на
   другие строки.
4. **Навигация профиля не переживает поворот экрана.** `page` не сохраняется в
   `onSaveInstanceState`; плюс ветка `PAGE_DEVICES` недостижима (мёртвый код) —
   «Устройства» открывают отдельный экран.
5. **Обращения к SQLite из главного потока** в `AssignActivity.render`,
   `ProfileActivity.renderPage`, `BadgesFragment.refresh` — риск ANR на больших таблицах.
